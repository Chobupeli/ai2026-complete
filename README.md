# AI — интерактивный гид / учебное серверное приложение

Самостоятельная автоматическая сборка по пособию PosobieProekt2024.pdf и исходному сайту пользователя. История не продолжает существующий репозиторий. Автор автоматической сборки указан отдельно; даты коммитов не имитируют прошлую работу.

## Быстрый запуск финального состояния
Node.js 20.6+, Git, локальный MongoDB. Скопировать .env.example в .env, заменить SESSION_SECRET длинной случайной строкой.

```
npm install
npm run seed
npm run check
node testTopic.js
node checkUser.js
npm start
```

Открыть http://localhost:3000. В финальной ветке отдельные страницы /topics/vision, /topics/patterns, /topics/actions, /topics/text доступны после входа через /logreg. Главная с лабораторией открыта всем. Повторный seed обновляет четыре темы без удаления других данных. Название базы задаётся в MONGO_URL; по умолчанию ai2026. Никакие пароли или дампы базы в архив не включены.

## Архитектура
- app.js: Express, EJS, сессии, middleware и обработка ошибок.
- bin/www: HTTP-сервер.
- routes/index.js: главная, формы регистрации/входа, выход.
- routes/topics.js: темы из MongoDB.
- models/topic.js и user.js: модели Mongoose.
- middlewares/: меню, текущий пользователь, контроль доступа.
- views/layout/page.ejs: общий макет ejs-locals.
- public/: исходные стили, скрипты и SVG. Canvas и квиз исполняются в браузере, а не вызывают внешний AI API.
- data.js, createDB.js: начальные данные и их загрузка.

## Ветки
28 учебных веток ai_4_2 … ai_10_8 и отдельная базовая main. Каждая следующая учебная ветка продолжает предыдущую; main оставлена базовой. Готовый проект находится в ai_10_8. STAGE.md описывает выбранный этап.

После переключения между этапами заново выполнить npm install. Seed появился в ai_6_3; для этапов до него команда npm run seed ещё не применяется. Скрипты проверки моделей работают только после появления соответствующих моделей.

## Отличия от буквального копирования пособия
Четыре Topic вместо трёх Cat; сохранён одностраничный AI-сайт. Полный frontend подключён в 5.2 вместе с общим меню. Bootstrap загружается через CDN и может немного влиять на исходный дизайн. Встроенное меню исходной главной остаётся своим адаптивным меню.
Хеширование паролей использует scrypt и случайную соль вместо устаревшего примера SHA-1. Пароли не выводятся в логи. Регистрация и вход разделены двумя кнопками, чтобы неверный логин не создавал аккаунт автоматически. Базовые сообщения об ошибках введены раньше 10.6, чтобы промежуточный сервер обрабатывал неверные данные; в 10.6 выделено оформление сообщений. Пробные модели названы Probe, а не Cat.

## Ограничения
Зависимости закреплены прямыми версиями, но package-lock.json не создан: установка npm здесь не выполнялась. После установки включите появившийся package-lock.json в собственный репозиторий. Node-модули, MongoDB и браузерные тесты в среде сборки отсутствуют. Проверка синтаксиса не равна проверке работающего приложения.
Это локальный учебный проект, не production-сервис: до публичного развёртывания необходимы CSRF-защита форм, ограничение частоты запросов, HTTPS, безопасные production-cookie, проверка зависимостей и пересмотр старого ejs-locals. Не используйте реальные пароли других сервисов.

## Проверка перед сдачей
1. npm install; затем seed, check и проверки моделей.
2. Главная: темы, история, canvas, генерация текста, квиз.
3. Незарегистрированный посетитель открывает /topics/vision: перенаправление на /logreg.
4. Регистрация нового логина, затем открытие всех четырёх тем.
5. Logout; вход правильным и неверным паролем. Неизвестный логин не регистрируется кнопкой «Войти».
6. После выхода защищённые страницы снова требуют входа.
7. Создать сессию, перезапустить Node и проверить сохранение входа (срок cookie один час).
8. В mongosh: use ai2026; db.topics.countDocuments() — ожидается 4 для новой базы; db.users.find({}, {username:1,hashedPassword:1,salt:1}); db.sessions.find(). Не публикуйте эти данные.
9. Неизвестный адрес возвращает 404. У вошедшего пользователя неизвестная тема тоже возвращает 404.
10. Заполнить имя, группу, учебное заведение и требования оформления в собственной документации.

Оценку определяет преподаватель; соответствие всем неуказанным требованиям не гарантируется. Историю автоматической сборки не выдавайте за последовательность собственных ручных изменений.
